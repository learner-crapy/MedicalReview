# 13 · 应用到本项目：多代理系统 × 医学问答

本项目的综述对象不是"患者接受某种治疗"，而是"模型—框架—基准"的计算实验。PRISMA 2020 仍然适用，但若干条目必须**显式改编并声明改编方式**——改编本身不是问题，**不声明就套用**才是。

## 13.1 分析单位的改变

传统系统综述：`Study → Participants → Outcome`

本项目：

```
Study × Framework × Backbone model × Benchmark × Experimental condition
```

一篇论文常包含多个模型、多个基准、多组消融，因此**提取表的一行不是一篇论文**，而是一个比较条件。这一变化会波及条目 5（分组规则）、17（研究特征表）、19（单研究结果）、20a（各综合的贡献研究）。必须在 protocol 中把"分析单位"单独写成一节。

同时注意 **study vs report**：同一工作的 arXiv 版 + 会议版 + 期刊扩展版是一个 study 的三份 report（见 `05`）。

## 13.2 框架改编：PICO 的对应物

| PICO 要素 | 本项目的对应 | 需要声明的内容 |
|---|---|---|
| **P**（对象） | 文本型医学考试式问答题目集（MedQA、MedMCQA、预先列明的 MMLU 医学子集） | 明确列出纳入的基准与子集名称、版本、split |
| **I**（干预） | LLM 多代理系统 | 必须给出 MAS 的操作化定义（见 13.3） |
| **C**（对照） | **使用相同基础模型、相同外部信息权限、可比推理预算的单代理基线** | 声明"无匹配基线的研究只进证据地图，不进主综合" |
| **O**（结局） | 主要：匹配条件下的准确率差值 ΔAcc；次要：token、成本、延迟、方差、失败率 | 主要结局必须唯一 |
| **S**（设计） | 报告原创定量实验的论文/会议论文/完整预印本 | 是否纳入预印本必须预先决定 |

在正文中这样声明（条目 4 与 5）：

> 本综述改编了 PICO 框架：由于评价对象为计算实验而非临床干预，"Population" 指基准题目集而非患者，"Comparator" 指匹配的单代理基线。这一改编及其理由在 protocol 中预先设定。

## 13.3 条目 5 的核心：MAS 的操作化定义

没有这条定义，整篇综述的可重复性为零。建议写法：

**纳入**：至少两个由 LLM 驱动、具有不同角色、状态或推理轨迹的 agent，在产生最终答案之前通过明确的消息交换、审议、批评、协商或层级聚合相互影响。

**单独分类（不并入主综合）**：
- 无交互的多次独立采样（self-consistency）
- 多模型简单投票 / 传统 ensemble
- 单一 LLM 顺序扮演多个角色但角色之间无独立状态
- 单代理 + RAG / 单代理 + 工具

**唯一的真正排除标准**（不是纳入标准的否定）：符合 MAS 定义、但**无法把多代理的贡献与 RAG、工具、额外采样区分开**的研究。这类研究可保留在证据地图中，但不进入主比较。

## 13.4 分面 vs 属性：哪些进检索式

| 概念 | 进检索式？ | 在综述中的位置 |
|---|---|---|
| multi-agent / debate / collaboration | ✅ 核心分面 | **主分组轴** |
| large language model / GPT / LLM | ✅ 核心分面 | 调节变量 |
| medical / clinical / MedQA / MMLU | ✅ 核心分面 | 分层 |
| RAG / tool use | ❌ | 提取字段 + 敏感性分析 |
| 模态（文本/多模态） | ❌ | 提取字段 + 纳入边界 |
| 题目难度 | ❌ | 效应调节变量 |
| 模型参数量 | ❌ | 效应调节变量 |

理由见 `07`：后四项不稳定地出现在标题/摘要中，进检索式会摧毁灵敏度。

## 13.5 条目 6、7：数据库

必须同时覆盖医学与计算机两侧：MEDLINE/PubMed、Embase、Scopus 或 Web of Science、IEEE Xplore、ACM DL、ACL Anthology、arXiv、medRxiv，加前向/后向引文追溯。

**arXiv 的特殊处理**必须预先写明：
- 是否纳入未经同行评议的预印本（建议纳入，但作为敏感性分析的一个维度）
- 预印本与正式版并存时以哪个为准
- 检索截止后预印本升级为正式版时如何处理

## 13.6 条目 11：没有现成的偏倚风险工具

RoB 2 与 ROBINS-I 都不适用。按 `09` 的做法自建领域并预注册。本项目建议的领域：

测试集选择完整性 / 基线可比性 / 模型版本可追溯性 / 随机性与重复运行 / 统计不确定性 / 测试集调参独立性 / 训练数据污染检查 / 选择性报告（基准、运行、prompt）/ 可复现性（代码、prompt、逐题预测）/ 多代理贡献的可归因性。

逐领域给 low / some concerns / high + 理由，**不加总分**，并预先声明通过敏感性分析进入综合。

可参考 MI-CLAIM、METRICS、TRIPOD-LLM 取条目灵感，但必须声明它们是报告框架而非经验证的偏倚风险工具。

## 13.7 条目 12、13：效应量与综合

**不要平均不同论文报告的绝对准确率。** 主效应用同一研究内的匹配差值：

```
ΔAcc(i,j) = Acc_MAS(i,j) − Acc_single(i,j)
```

其中 i 为研究、j 为基准/条件。

必须预先承认的三个统计障碍（写进 protocol 的 13b 与 13d）：
1. 同一测试集上的两个系统是**配对数据**，缺少逐题一致/不一致计数时，差值的标准误往往无法正确计算。
2. 一篇论文产生的多个比较**不相互独立**（需多层模型或每研究只取一个主要比较）。
3. 参数量分析会被模型家族、发布年代、医学微调同时混杂。

**结论：不要预先承诺 meta-analysis。** 在 protocol 中写明：只有当匹配比较数量足够、结局定义一致、方差可得时才做定量合并；否则按 **SWiM 九条**做结构化综合（见 `08`）。并明确排除朴素 vote counting 作为主要综合方法。

## 13.8 条目 13e：题目难度作为调节变量

难度不是研究的分类，而是效应的调节变量。证据优先级（写进 protocol，不可事后决定）：

1. 数据集自带且经过验证的难度标签
2. IRT 参数、考生通过率或专家难度评级
3. 由独立单代理基线的逐题正确率形成的**预设**分位组
4. 原作者提供但未经验证的难度标签

**不可接受**：把 MMLU/MedMCQA/MedQA 直接等同于低/中/高难度；用待评价系统自身的错误率定义难度。

若多数研究不提供逐题结果，这一子问题应预先写成"仅在数据允许时进行的次级分析"。

## 13.9 条目 15、22：GRADE 的改编

GRADE 为临床证据设计，用于本项目时必须声明改编，并特别注意两个降级维度：

- **间接性（indirectness）**：在考试式选择题上的准确率提升，用于推断真实临床推理能力，属于高度间接的证据——这应当是本综述最重要的一次降级，也是最有价值的方法学结论。
- **发表偏倚**：本领域的特有形式是"只有跑赢基线的多代理框架才会被发表"，以及同一框架只报告最好的那次运行/基准/prompt。

对应到讨论（23a、23d）：明确区分 **efficacy（基准条件下有效）** 与 **effectiveness（真实临床中有效）**，不要跨越。

## 13.10 条目 24a：注册去哪里

本综述的直接结局是 benchmark 性能而非健康结局，**PROSPERO 可能不予收录**。做法：
1. 先向 PROSPERO 询问是否在范围内；
2. 若不在，预注册到 **OSF Registries**，取得 DOI；
3. 在条目 24a 中如实说明这一过程与理由。

## 13.11 条目 27：本项目尤其重要

综述对象本身是计算研究，你自己的综述也应当是可复现的：提取表模板、逐条提取数据、偏倚判断、分析脚本、检索式原文全部上传 OSF/Zenodo 并给出 DOI。这同时也是对纳入研究提出同一要求的正当性来源。

## 13.12 仍需决定的三件事（决定前不要建检索式）

1. **多模态研究进不进主分析？**（建议：不进，只进证据地图）
2. **非交互式 ensemble / self-consistency 算不算 MAS？**（建议：单独编码，不进主合并）
3. **是否要求必须有匹配的单代理基线？**（建议：主分析要求；无基线者仅进描述性地图）

这三项一旦确定，即可按 `06` 撰写 protocol、按 `07` 构建检索式、按 `05` 建立流程图计数表。
