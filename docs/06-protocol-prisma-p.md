# 06 · Protocol 与注册（PRISMA-P 17 条）

## 6.1 为什么必须先写 protocol

系统综述之所以被视为最高级别的证据，靠的是**预先设定**：纳排标准、结局、亚组、综合方法都在看到数据之前确定。否则综述作者拥有与原研究作者同样多的"研究者自由度"，可以事后挑选出想要的结论。

PRISMA 2020 的条目 24a–24c 因此把注册与 protocol 提升为独立一节，并要求报告**任何修订**。

对应关系：
- **写 protocol** → 用 PRISMA-P（17 条）
- **写最终报告** → 用 PRISMA 2020（27 条）
- **报告修订** → 条目 24c

## 6.2 PRISMA-P 2015 完整清单

出处：Moher D, Shamseer L, Clarke M, et al. *Syst Rev* 2015;4:1.

### 管理信息（Administrative information）

| # | 条目 |
|---|---|
| 1a | 标题中标明本文是一份系统综述的 protocol |
| 1b | 若为既有综述的更新，标题中说明 |
| 2 | 若已注册，给出注册库名称（如 PROSPERO）与注册号 |
| 3a | 所有 protocol 作者的姓名、单位、邮箱；通讯作者的通信地址 |
| 3b | 描述各作者贡献，并指明综述的担保人（guarantor） |
| 4 | 若本 protocol 是对既有 protocol 的修订，说明并列出修改；否则，**陈述将如何记录未来的重要修订** |
| 5a | 财务或其他支持来源 |
| 5b | 资助方/赞助方名称 |
| 5c | 资助方、赞助方、所属机构在 protocol 制定中的角色 |

### 引言（Introduction）

| # | 条目 |
|---|---|
| 6 | 在已知知识背景下描述做本综述的理由 |
| 7 | 明确陈述综述要回答的问题，参照 PICO 各要素 |

### 方法（Methods）

| # | 条目 |
|---|---|
| 8 | **纳排标准**：研究特征（PICO、设计、场景、时间范围）与报告特征（年份、语言、发表状态） |
| 9 | **信息源**：所有拟用信息源（电子数据库、联系作者、试验注册库、灰色文献）及计划覆盖日期 |
| 10 | **检索策略**：至少给出一个电子数据库的检索式草案（含计划的限制条件），使之可被重复 |
| 11a | **研究记录**：整个综述过程中管理记录与数据的机制 |
| 11b | 各阶段（筛选、合格性判定、纳入合并）的选择流程（如双人独立） |
| 11c | 计划的数据提取方法（预试表格、是否双人独立），以及向研究者索取/核实数据的流程 |
| 12 | **数据条目**：列出并定义所有拟提取变量（PICO 条目、资助来源等）、预设的假设与简化 |
| 13 | **结局与优先级**：列出并定义所有拟提取结局，标明主要与附加结局的优先级及理由 |
| 14 | **单研究偏倚风险**：预期使用的评价方法，在结局层面还是研究层面进行；**并说明该信息将如何用于数据综合** |
| 15a | **数据综合**：在何种标准下进行定量合并 |
| 15b | 若适合定量合并：计划的汇总测量、数据处理方法、合并方法，以及一致性探索（如 I²、Kendall's tau） |
| 15c | 其他拟进行的分析（敏感性分析、亚组分析、meta 回归） |
| 15d | 若不适合定量合并，说明计划采用的总结类型 |
| 16 | **元偏倚**：计划的元偏倚评估（研究间发表偏倚、研究内选择性报告） |
| 17 | **累积证据确信度**：将如何评价证据体的强度（如 GRADE） |

> 注意条目 14 的后半句与条目 15c：**偏倚评价必须预先规划好"怎么用"**，而不是做完放附录。这是文献中最常见的空转。

## 6.3 在哪里注册

| 平台 | 适用 | 说明 |
|---|---|---|
| **PROSPERO** | 有健康相关结局的系统综述 | 国际主流；免费；提交后有审核与排队；范围综述、文献计量学综述通常**不收** |
| **OSF Registries** | 任何学科 | 即时生效、可加时间戳、可公开 protocol 全文；方法学/计算类综述的常用去处 |
| **INPLASY / Research Registry** | 补充选项 | 审核快，但认可度不及 PROSPERO |
| **期刊发表 protocol** | *Systematic Reviews*、*BMJ Open* 等 | 经过同行评议，权威性最高，但耗时数月 |

**若综述的直接结局不是健康结局（例如本项目的结局是 benchmark accuracy），PROSPERO 可能不予收录。** 正确做法是：先向 PROSPERO 询问是否在范围内；若不在，注册到 OSF 并在正文条目 24a 中如实说明（"本综述未在 PROSPERO 注册，因其结局非健康结局；protocol 已于 OSF 预注册，DOI: …"）。

## 6.4 Protocol 修订的记录规范

保留一份 `protocol-amendments.md`，每次修订记录：

```
日期 | 修改了哪一条 | 修改前 | 修改后 | 理由 | 是否已看过任何结果数据（是/否）
```

最后一列是关键。**在看到结果之前的修订**通常是可接受的方法学完善；**在看到结果之后的修订**必须特别标注，并在条目 24c 与讨论的局限部分说明其对结论可能的影响。

## 6.5 Protocol 完成度自检

- [ ] 17 条 PRISMA-P 条目全部有内容（不适用的写"不适用"并说明理由）
- [ ] 纳排标准写在检索策略**之前**（逻辑顺序：先说找什么，再说怎么找）
- [ ] 每个排除标准都不是纳入标准的简单否定
- [ ] 主要结局唯一且定义明确；次要结局有优先级
- [ ] 亚组分析已列出完整清单并说明假设机制（不能事后加）
- [ ] 偏倚评价工具已选定，且写明结果如何进入综合
- [ ] 已声明"不适合定量合并时"的替代方案（15d）
- [ ] 已写明修订记录机制（条目 4）
- [ ] 已获得注册号或 OSF DOI
