# 07 · 检索的构建与报告（PRISMA-S 16 条）

PRISMA 2020 的条目 6、7 只用两句话概括了检索的报告要求；**PRISMA-S** 把它展开成 16 条，是目前最细的检索报告规范。

出处：Rethlefsen ML, Kirtley S, Waffenschmidt S, et al. *Syst Rev* 2021;10:39.

## 7.1 PRISMA-S 16 条

### 信息源与方法（Information Sources and Methods）

| # | 条目 | 要求 |
|---|---|---|
| 1 | **Database name** | 逐个列出检索的数据库名称，并注明各自的平台 |
| 2 | **Multi-database searching** | 若在同一平台同时检索多个数据库，注明平台名并列出所有数据库 |
| 3 | **Study registries** | 列出检索过的研究注册库 |
| 4 | **Online resources and browsing** | 描述有目的地检索或浏览过的在线/纸本来源（目录页、会议论文集、网站）及做法 |
| 5 | **Citation searching** | 说明是否检查了被引/引用文献，以及定位方法（翻参考文献表、引文索引、邮件提醒） |
| 6 | **Contacts** | 说明是否通过联系作者、专家、厂商等获取额外研究或数据 |
| 7 | **Other methods** | 描述其他信息源或检索方法 |

### 检索策略（Search Strategies）

| # | 条目 | 要求 |
|---|---|---|
| 8 | **Full search strategies** | 给出每个数据库与信息源的检索式，**按实际运行时的原样复制粘贴** |
| 9 | **Limits and restrictions** | 说明未使用限制，或描述所用限制（日期、语言、研究设计）**并给出理由** |
| 10 | **Search filters** | 说明是否使用了已发表的检索过滤器（原版或改编），并引用出处 |
| 11 | **Prior work** | 说明是否改编或复用了其他综述的检索式，并引用该综述 |
| 12 | **Updates** | 报告更新检索的方法（重跑检索、邮件提醒等） |
| 13 | **Dates of searches** | 对每个检索式给出最后一次检索的日期 |

### 同行评议（Peer Review）

| # | 条目 | 要求 |
|---|---|---|
| 14 | **Peer review** | 描述检索式的同行评议过程 |

### 记录管理（Managing Records）

| # | 条目 | 要求 |
|---|---|---|
| 15 | **Total records** | 记录每个数据库与其他来源各自获得的记录总数 |
| 16 | **Deduplication** | 描述去重流程与所用软件 |

## 7.2 怎么构建检索式：分面分析（facet analysis）

分面理论出自印度图书馆学家 S.R. Ranganathan。做法：把综述问题拆成若干**互不重叠**的概念分面，每个分面内部穷举同义词与受控词。

```
facet 内部：OR        facet 之间：AND
```

> **最常见的检索失败原因，是在同一个分面内部误用了 AND。**

### 构建步骤

1. **拆分面**：从 PICO（或你改编的框架）出发，通常取 2–4 个分面。分面太多 = 检索过窄。
2. **每个分面收集两类词**：
   - 自由词（title/abstract）：同义词、缩写、拼写变体、单复数、截词
   - 受控词（index terms）：PubMed 的 MeSH、Embase 的 Emtree、CINAHL headings
3. **验证受控词**：查 MeSH Browser（meshb.nlm.nih.gov）确认其 scope note 与你的意图一致，别想当然。
4. **预检索（scoping search）**：JBI 三步法——① 用初始关键词检索，检查早期命中文献里出现的新词；② 把完整策略用到每个数据库；③ 手工翻查所有纳入研究的参考文献。
5. **sentinel paper 召回测试**：先手选 5–10 篇你**确知**该被纳入的论文，检索式必须全部命中。漏掉任何一篇，就回去改检索式（并记录这次迭代）。
6. **逐库转换语法**：字段标签、截词符、邻近算符在各平台都不同，必须逐库重写而不是复制。
7. **同行评议**：按 **PRESS**（Peer Review of Electronic Search Strategies）清单请信息专家或同行复核：检索问题翻译、布尔逻辑与邻近算符、受控词、自由词、拼写与语法、限制与过滤器。

### 一个重要判断：哪些概念**不**进检索式

不是所有你关心的变量都该进检索式。判断标准是：**这个概念在标题/摘要中是否被稳定地表述？**

- 稳定出现 → 进检索式（否则漏检）
- 只在正文/表格中出现 → **不进检索式，进提取表**

典型的"不进检索式"的变量：是否使用检索增强、模型参数量、题目难度、成本与延迟。把它们塞进检索式会把灵敏度毁掉。

## 7.3 灵敏度与特异度的权衡

| | 灵敏度优先 | 特异度优先 |
|---|---|---|
| 结果 | 命中多、噪声大 | 命中少、可能漏检 |
| 适用 | 系统综述（默认） | 快速综述、范围极窄的问题 |
| 代价 | 筛选工作量大 | 遗漏风险，威胁综述效力 |

系统综述默认选灵敏度优先，用筛选阶段而不是检索阶段去除噪声。

## 7.4 数据库选择

医学与计算机交叉的综述，两边都要覆盖：

| 类别 | 数据库 |
|---|---|
| 医学 | MEDLINE/PubMed、Embase、CINAHL、PsycInfo、Cochrane Library |
| 计算机/工程 | IEEE Xplore、ACM Digital Library、Scopus、Web of Science |
| 自然语言处理 | ACL Anthology、DBLP |
| 预印本/灰色文献 | arXiv、medRxiv、bioRxiv、OpenGrey |
| 注册库 | ClinicalTrials.gov、ISRCTN（若涉及临床评估） |

**Google Scholar**：索引不稳定、不可复现，可用于预检索和查漏，不作为主要来源。若使用，说明检索日期与截取的结果数（常见做法：只取前 200–300 条）。

## 7.5 记录管理与去重

1. 各库导出 `.ris`/`.nbib`，**保留原始未去重文件**（存档）。
2. 用 Zotero / EndNote / Covidence / Rayyan 自动去重，再人工抽样复核。
3. 计算机领域特别注意：同一研究的 arXiv 版、会议版、期刊版**不是重复记录而是同一研究的多份 report**，应在筛选阶段合并为一个 study，并在流程图里体现（见 `05`）。
4. 记录每个来源的记录数（PRISMA-S 条目 15）与去重方法（条目 16）。

## 7.6 检索阶段自检

- [ ] 纳排标准已定稿（检索必须在标准之后）
- [ ] 分面表已列出：每个分面的自由词 + 受控词
- [ ] 分面内用 OR、分面间用 AND，逐行检查过
- [ ] sentinel paper 测试 100% 召回
- [ ] 每个库的检索式单独转换并保存原文
- [ ] 已做 PRESS 同行评议（或至少一位他人复核）
- [ ] 每个库的记录数、检索日期、平台已记录
- [ ] 计划了更新检索的方式（条目 12）
- [ ] 完整检索式已准备好作为附录提交
